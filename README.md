## How I like to build

- Start with the actual user problem, not the feature list.
- Build the smallest useful version, then improve it with real feedback.
- Keep interfaces intentional and systems understandable.
- Treat AI as a product capability that needs thoughtful UX, evaluation, and guardrails.
- Prefer shipping a well-finished slice over describing a sprawling roadmap.

## For collaborators and AI agents

1. Read the target repository’s README and local contribution guidance before changing anything.
2. Keep implementation scoped to the request; avoid unrelated refactors and speculative abstractions.
3. Preserve existing conventions, validate the relevant build or tests, and explain any limitation honestly.
4. Keep personal projects separate from my work at [Pulse](https://www.pulsegen.io/) unless the repository explicitly connects them.
